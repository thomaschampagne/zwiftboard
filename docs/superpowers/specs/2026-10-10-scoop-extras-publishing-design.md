# Design: scoop-extras publishing on CI

Date: 2026-10-10

## Intent and why

Today zwiftboard ships only as GitHub release assets (exe + zip + sha256).
Windows users must hand-download each release. `scoop install zwiftboard`
from the community [extras bucket](https://github.com/ScoopInstaller/Extras)
gives one-command install + `scoop update zwiftboard` on every new release.
This design adds that publishing path, fully automatic per release.

## Goals

- `scoop install zwiftboard` installs the latest release exe; `scoop update` bumps it.
- Zero manual steps when a semantic-release cut lands on `main`.
- Manifest follows extras-bucket conventions so the PR passes review.
- README documents the scoop install path.
- Existing GitHub release flow stays intact (semantic-release, assets, checksums).

## Non-goals

- Own scoop bucket (user chose the community extras bucket instead).
- winget / Chocolatey / any other package manager.
- Auto-merge of the extras PR (extras maintainers merge; out of our control).
- Version pinning / multiple concurrent versions in the bucket.
- Changing the Go app itself, config, or TUI.

## Anti-goals

- Breaking the current GitHub release layout beyond the approved asset rename.
- Any manual copy/paste step per release.
- Manifest hacks (pre_install renames, extract_dir tricks) that extras rejects.

## Constraints

- semantic-release tags are `X.Y.Z` **without** a `v` prefix (`.releaserc.json`
  `tagFormat: "${version}"`). checkver regex and autoupdate URL must match
  bare `X.Y.Z` tags.
- Release assets today: `zwiftboard-windows-amd64.exe`,
  `zwiftboard-windows-amd64.zip`, `checksums.txt`. Scoop shims the asset
  filename, so a clean command name requires renaming.
- The extras repo requires PRs (from forks); CI cannot push directly.
- Extras has a quality/popularity bar — PR may be rejected. Acceptable; no
  fallback bucket planned.
- GitHub Actions `GITHUB_TOKEN` cannot open PRs on *other* repos; a PAT is required.

## Decisions (made)

1. **Bucket target**: `ScoopInstaller/Extras`, PR-based, full auto. No existing
   zwiftboard manifest (verified 2026-10-10) — first PR adds the file.
2. **Asset rename**: `scripts/build-release.sh` produces `zwiftboard.exe`
   (and `zwiftboard.zip`). The version is in the release tag, so the
   filename stays clean for scoop. Release asset labels in
   `.releaserc.json` updated to match.
3. **PR automation**: new `scoop` job in `.github/workflows/release.yml`,
   `needs: release`. It reads the just-published tag via
   `gh release view --json tagName`, renders the manifest, then uses
   `peter-evans/create-pull-request@v6` with `push-to-fork: true` against a
   checkout of `ScoopInstaller/Extras`, so the PR comes from the PAT owner's
   fork as extras requires. Job is gated on a new release actually being
   published (latest tag captured before semantic-release, compared after —
   semantic-release exits 0 even when it publishes nothing, and
   `gh release view` would otherwise return the previous tag).
4. **Credential**: user creates a personal access token (repo scope) and adds
   it as repository secret `SCOOP_EXTRAS_PAT`. Not stored in the repo.
5. **Manifest**:    `bucket/zwiftboard.json` in the `ScoopInstaller/Extras` repo, generated by
   a small script (`scripts/scoop-manifest.sh`) taking version as `$1`.
   checkver uses the GitHub source; autoupdate URL points at the exe asset;
   `bin` shims `zwiftboard.exe`. No static hash — scoop computes it at update
   time (current extras convention).
6. **README**: new Install section with the one-line
   `scoop bucket add extras ...; scoop install zwiftboard` flow plus badge.
   AGENTS.md release notes updated to mention the scoop job.

## Left to the builder

- Exact manifest JSON fields/description text (follow existing extras
  manifests as reference).
- PR title/body wording (match extras contributing guide).
- Whether the manifest script is bash or `go run` (repo convention is bash
  for scripts — default bash).
- Handling of PR-already-open edge cases (create-pull-request is idempotent
  enough; builder may note it).
