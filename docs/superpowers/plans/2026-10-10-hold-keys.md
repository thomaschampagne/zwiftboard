# Hold keys while a button is pressed (steering support)

Date: 2026-10-10. Status: **implemented** (all checks green).

## Goal

Emulate a long key press: a mapped key stays **down** while its button is
held and goes **up** on release. Needed for steering in MyWhoosh (hold
left/right), previously only a tap per press was possible.

## Design

All mapped buttons hold (no config toggle — holding menu keys is harmless).

Two dedup layers for the mirrored pair (one press = same frame from both
units = two handlers):

1. **Edge-triggered diff** (`ButtonHandler`, `internal/ble/buttons.go`):
   only bits that changed since the previous frame act. Identical
   retransmits within one handler change nothing.
2. **Per-VK idempotency** (`holdKeys`, `internal/ble/buttons.go`): package-level
   `heldVK` set shared across ALL handlers. Second handler's Down finds the
   VK already held → sends nothing; mirrored Up finds nothing held → sends
   nothing. `Session` wires `keys.Down`/`keys.Up` through `holdKeys`.

Removed: `claimTap`/`lastTapByName`/`TapDebounce` and the `-debounce` flag —
the diff already dedups, and a time window would wrongly suppress a fast
re-press Down (press/release/press within 200ms).

Stuck-key safety: `ble.ReleaseAll()` (new) releases every held VK via
`keys.ReleaseVK`; `Session` defers it, so a keepalive failure (real
disconnect) can never leave a key stuck down.

`OnTap` (TUI highlight) fires per pressed transition — twice for a mirrored
press; observational only, highlight is idempotent. The key itself is
pressed once.

## Auto-repeat fix (same day, after first hardware test)

Observed on hardware: holding a mapped letter (A/Z) did NOT repeat in
Notepad — the caret stayed put — while arrow keys felt held. Cause: a
synthetic `keybd_event` down is a single event with **no OS auto-repeat**.
Games (MyWhoosh) poll the key state, so the hold works there; text apps
need the repeated `WM_KEYDOWN` a physical keyboard produces while held.

Fix (`internal/keys/tap_windows.go`): `Down` starts keyboard auto-repeat —
after a 250ms delay (Windows' shortest repeat delay) it re-sends the press
every ~33ms (default repeat rate) until `Up`/`ReleaseVK` stops the
goroutine. Per-VK stop map, idempotent start; `Tap` stays Down+Up.
No flag/config: fixed at real-keyboard values.
